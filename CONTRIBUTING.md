# Contributing to oak

Thanks for your interest in `open-agent-kit` (`oak`).

### Project mission

oak is the **production runtime toolkit for agents**. A sandbox for the
agent's tool calls with cross-server reconnect, resumable sessions safe
under multiple servers, and per-framework session wrappers.
Framework-neutral. Multi-vendor. Apache-2.

We ship mechanism; users ship policy. Two public sub-modules + a CLI is the
entire v0.1 surface.

### Repo layout

```
packages/
  oak-workspace/      Workspace Protocol + Local + E2B backends
  oak-session/        attach/end + state-store + trace-source + lease
                      + per-framework wrappers (oak.session.openhands.* first)
  oak/                umbrella CLI: demo, init, protocols, version
docs/                 architecture, principles, extending guides, contract tests
docs/design/          per-module design docs (workspace, session)
```

Three published distributions: `oak-workspace`, `oak-session`, `oak`. Each
versioned independently.

### Dev setup

```bash
git clone https://github.com/<org>/open-agent-kit.git
cd open-agent-kit
uv sync
```

`uv` is the dependency manager for the workspace. `uv sync` installs every
package in editable mode with all dev extras.

### Code style

Both must pass on every PR:

```bash
uv run ruff check
uv run mypy --strict packages/oak-workspace/src/oak_workspace \
                     packages/oak-session/src/oak_session \
                     packages/oak/src/oak_cli
```

- `ruff` enforces lint + import order + formatting.
- `mypy --strict` is mandatory for all public surface code. No `# type: ignore`
  without a comment explaining why.

### Tests

```bash
uv run pytest packages/
```

Every Protocol ships a contract test suite. New backends MUST run the
contract suite for that Protocol and pass it before merge.

### PR checklist

Before requesting review:

- [ ] `uv run pytest packages/` passes
- [ ] `uv run mypy --strict ...` clean (see paths above)
- [ ] `uv run ruff check` clean
- [ ] Contract tests pass if you touched or added a Protocol implementation
- [ ] Docs updated (README, `docs/design/<module>.md`, or `docs/extending-oak.md`
      as appropriate)
- [ ] `CHANGELOG.md` entry added under `[Unreleased]`
- [ ] Commit messages have no emojis and no AI-attribution lines

### Adding a backend or framework adapter

The four extension paths (workspace backend, trace-source adapter,
state-store backend, per-framework session wrapper) are covered in detail
in [`docs/extending-oak.md`](docs/extending-oak.md). Each follows the same
shape: implement a small Protocol, pass the contract suite, optionally
register an entry point.

Community backends live in their own packages and register via Python
entry points. The core repo ships a small named set of reference backends;
it is not a catalog.

### New modules

If you propose adding a new top-level module, open an issue first with:

1. The production use case
2. Why no existing tool fits
3. The smallest Protocol that solves it

PRs that introduce new modules without prior issue discussion will be sent back for design conversation first.

### Commit messages

- No emojis. Anywhere. In code, in comments, in commit messages.
- No AI-attribution lines (`Co-Authored-By: <model>`, "Generated by", etc.).
- Short, lowercase, imperative. Match the existing log style.
